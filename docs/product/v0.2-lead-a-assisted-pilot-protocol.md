# v0.2 Lead A Assisted External Pilot Protocol

Gate 8 operational protocol for the v0.2 external-testability validation loop.

This is not an engineering gate. It fixes the pilot procedure and evidence packet **before** a real target-cohort participant runs the workflow, so success and failure are adjudicated against frozen criteria rather than improvised after the session.

Version establishment semantics remain owned by `versioning.md`. This document operationalizes Gate 8 only.

## Validation Question

> **Can a real target-cohort person understand and complete a credible Lead A review workflow?**

Canonical v0.2 establishment requires one qualifying facilitated target-cohort session. Built-in ASR, Gate 5–7 capabilities, Manual Replacement, promotion, reuse value, media playback, and deterministic cross-material reuse demonstration are **not** prerequisites.

## Qualifying Session

### Participant

- Real target-cohort human (see `docs/discussion/2026-07-09.md` for cohort context).
- **Not** Ezra or any project implementer acting as the participant.

### Material

- Real speech-derived SRT.
- Participant-owned, owner-authorized, or otherwise explicitly authorized for this pilot.
- External SRT is allowed; built-in ASR is not required.

Do not manufacture errors, synthetic `ReviewCase`s, or deliberately corrupted subtitles for testing convenience. Use the material as it exists for the authorized review task.

### Facilitation

- Facilitation is allowed.
- UI and mechanics explanation is allowed.
- The facilitator **must not** tell the participant which correction decision to make.

`decision_content_coaching` must remain **zero** for a qualifying session.

### Prepared Inputs

- SRT may be prepared beforehand.
- Session terms may be prepared beforehand.
- Term-authoring UX is **not** being validated in v0.2.

## Minimum Workflow

The participant must personally complete:

```text
open or create durable local session
→ understand review queue
→ inspect actual ReviewCases / context / evidence
→ make their own human decisions
→ reach complete review disposition
→ inspect current reviewed projection
→ export reviewed output
→ identify what the output represents
```

Manual Replacement, promotion, and reuse are available product capabilities but are **not** required for v0.2 establishment. v0.2 is not validating v0.3 reuse value. If the real material naturally requires Manual Replacement, use the normal product flow.

## Frozen Establishment Criteria

Adjudicate the pilot only against the criteria below. Do not add post-hoc success conditions.

```yaml
qualifying_participant: UNEVALUATED  # PASS | FAIL
real_authorized_material: UNEVALUATED  # PASS | FAIL
participant_operated_workflow: UNEVALUATED  # PASS | FAIL

workflow_completion:
  session_created_or_opened: UNEVALUATED  # PASS | FAIL
  review_cases_understood_enough_to_act: UNEVALUATED  # PASS | FAIL
  all_cases_dispositioned: UNEVALUATED  # PASS | FAIL
  reviewed_projection_reached: UNEVALUATED  # PASS | FAIL
  export_completed: UNEVALUATED  # PASS | FAIL

output_legibility:
  participant_can_identify_reviewed_output: UNEVALUATED  # PASS | FAIL
  participant_understands_that_machine_findings_are_not_authority: UNEVALUATED  # PASS | FAIL
  participant_understands_their_decisions_control_reviewed_output: UNEVALUATED  # PASS | FAIL

blocking_product_failure: none
```

**v0.2 establishment requires all core criteria above to be PASS** and `blocking_product_failure: none`.

Record the adjudication in `establishment-evaluation.md` (from `establishment-evaluation.template.md`) after the session. Do not pre-fill PASS before adjudication.

### Explicitly Out Of Scope For Pass/Fail

The following may be observed but **must not** determine v0.2 establishment:

- user likes the product
- would pay
- time saved
- better than current workflow
- reuse is useful
- ASR is accurate

Those belong to later version validation or commercial investigation.

## Machine Run Facts

v0.1 already defines inspectable run facts the implementation can record reliably: transcript and session-term counts, candidate counts, decision counts, ledger events, accepted replacements, affected segments, and local session timing. See `v0.1-execution-order.md`. These are run facts, not precision, recall, correctness, or workflow-value claims.

Gate 8 adds the human-operation layer in `session-observation.json` and `facilitator-log.md`.

## Human Evidence Capture

Record at minimum:

| Field | Location |
| ----- | -------- |
| pilot duration | `session-observation.json` |
| number of ReviewCases | `session-observation.json` |
| decision breakdown | `session-observation.json` |
| number of facilitator interventions | `facilitator-log.md` |
| intervention category | `facilitator-log.md` |
| errors encountered | `session-observation.json`, `facilitator-log.md` |
| recovery or retry required | `session-observation.json` |
| export success | `session-observation.json`, `export-manifest.json` |
| participant completed workflow yes/no | `session-observation.json` |

### Facilitator Intervention Categories

Record only:

- `navigation_help`
- `concept_explanation`
- `error_recovery_help`
- `participant_question`

Also record:

```text
decision_content_coaching = 0 required
```

Any `decision_content_coaching` intervention disqualifies the session as a qualifying establishment run unless the owner explicitly records a successor pilot.

## Participant Post-Session Questions

Ask exactly these four questions. Do not lead the participant.

1. 「你覺得這個畫面主要要你做什麼？」
2. 「剛才哪些修改是 VoxProof 自己決定的，哪些是你決定的？」
3. 「哪一個輸出是你剛才審完後的字幕？」
4. 「有哪個步驟你不知道下一步該做什麼？」

Questions 1–3 are comprehension evidence. Question 4 is friction observation.

Record answers in `participant-response.md`.

## Sensitive Material Policy

- Do **not** commit transcript text, audio, video, reviewed exports, or other sensitive participant material to the repository.
- Input and export manifests store SHA-256 digests, cue counts, duration where available, authorization basis, and source type only.
- Use pseudonymous participant IDs such as `lead-a-01`; do not record legal names in committed artifacts.
- Local screen or session recording is optional with participant consent; recording is **not** an establishment prerequisite.

## After The Pilot

```text
Lead A pilot evidence
→ evidence adjudication
→ explicit v0.2 establishment decision
→ v0.2 CLOSED   (if all core criteria PASS)
```

If the pilot FAILs:

- retain negative evidence;
- do not erase or overwrite the failed run;
- decide the smallest corrective action, if any;
- run a successor pilot under a new packet directory if needed.

A failed pilot does not authorize silent criteria changes, feature expansion, or retroactive PASS.
